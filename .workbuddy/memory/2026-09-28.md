# 2026-09-28 便携桌面 GPU 占用排查

## 问题：启动即 30% GPU + 高 CPU

## 根因（已实锤，A/B 实测）
`MainWindow_Loaded` 里 `PlayEmptyStatePulse()` 无条件启动 `EmptyStatePulse`
（`RepeatBehavior="Forever"` 呼吸动画）。列表有 27 项时 EmptyState 虽 Collapsed，
动画时钟仍在每帧 tick → 每帧全窗重渲染（AllowsTransparency 分层窗口 +
WindowBorder 上 BlurRadius=30 全窗 DropShadowEffect，每帧都过一遍模糊）→ GPU 30%。

启动时序漏洞是关键：`ReloadItems()`（内部 UpdateEmptyState，此时 _emptyStatePulse
还是 null，Stop 是空操作）→ 之后才 `PlayEmptyStatePulse()` 无条件 Begin。
所以「列表非空就停」的逻辑在启动路径上永远拦不住它。

## 修复（三处）
1. `UpdateEmptyState()` 成为动画生命周期唯一管理者：懒加载 `_emptyStatePulse ??=`，
   count==0 且未播 → Begin；count>0 且在播 → Stop + 清 Opacity 动画。
   用 `_pulseRunning` 标志位，不用 `GetCurrentState()`（从未 Begin 过的
   Storyboard 调它会抛 InvalidOperationException）。
2. `PlayWindowEntrance()` 两个动画加 Completed 处理器：值定住 + `BeginAnimation(prop, null)`
   摘除。默认 FillBehavior.HoldEnd 会让时钟永远挂着。
3. `ItemCard.PlayEntrance()` 的 Storyboard 同样加 Completed 摘除（27 卡 × 2 时钟）。
4. 删除 `PlayEmptyStatePulse()`，Loaded 里不再调用。

## 验收数据（Get-Counter '\GPU Engine(*)\Utilization Percentage' 按 pid 过滤）
- 修复前：GPU 30.6%，CPU 持续 ~80%/核
- 修复后：GPU 0%，CPU 启动后零增长；界面 27 项渲染正常；单测 8/8 过

## 排查过程中的大坑（下次必看）
- **CompositionTarget.Rendering 挂 handler 本身就会强制 WPF 每帧渲染**——
  用它做「每秒渲染计数」诊断时，观察者效应会污染全部实验（所有变体都 ~90fps）。
  诊断渲染风暴只能用外部观测：GPU engine counter 按 pid 过滤 + 进程 CPU 时间增量。
- 沙箱里 Start-Process 起的 GUI 进程在**命令结束时被回收**，跨命令查进程会发现
  "进程没了"，别误判成崩溃。验证存活要和启动放同一条命令里。
- PowerShell 的 Add-Type 被沙箱拦截（编译 .NET 代码）；截图用 Python venv +
  PIL，抓被遮挡的 WPF 窗口用 ctypes `PrintWindow(hwnd, hdc, 2)`（PW_RENDERFULLCONTENT），
  CopyFromScreen 只能截到盖在上面的别的窗口。

  （含 pillow），截图脚本模板 `C:/Users/15610/.workbuddy/tmp/pd_shot_pw.py`。
