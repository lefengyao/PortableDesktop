## 交付后修复（09:30）：图标整片消失
**根因**：`MainWindow.xaml.cs` 漏写了 DataTemplate 要绑定的公开属性
（只有私有字段 `_iconExtractor`，没有 `public IconExtractorService IconService`）。
XAML 里 `IconService="{Binding IconService, RelativeSource={RelativeSource AncestorType=Window}}"`
找不到宿主属性 → 静默 null → `ItemCard.ApplyItem()` 的 `if (Item is null || IconService is null) return;`
直接返回，图标永远没赋值。**WPF 绑定失败不抛异常、只在调试输出留一行 trace，编译期查不出来。**

**修法**：① 补上公开属性；② 把 `IconExtractorService.Shared`（进程级共享实例）设为
`ItemCard.IconService` 依赖属性的默认值，注入失效时也能兜底。
顺带修掉主题下拉框显示 record ToString 的问题（`ThemeInfo` 覆写 `ToString() => DisplayName`）。

**定位手法（可复用）**：
1. 卡片和名称正常、只有图标空 → 说明数据绑定通了，问题在图标那一步；
2. 用 csc 直接把 `IconExtractorService.cs` 编成独立控制台探针跑（不经过 NuGet），
   打印位图尺寸/不透明像素占比 → 证明 Win32+WPF 取图标链路本身没问题，排除法锁定绑定；
3. 给 `ApplyItem` 临时加文件日志，一次运行就打印出 `IconService=null` 且其变更回调从未触发 → 确诊。

**未提交前顺手发现的两个坑**：
- 窗口被最小化时 `GetWindowRect` 返回 157x25、位置 (-16000,-16000)——看到这个尺寸就是最小化了，`ShowWindow(SW_RESTORE)` 后恢复 787x604。
- 截图要走 `SetProcessDpiAwareness(2)`，否则 200% 缩放下坐标会被虚拟化（767x604 vs 实际 1574x1207）。
